# Wallet notes

zwap's browser wallet is a self-custodial Zenon address, not a hosted or
custodial service.

- The wallet is a BIP39 mnemonic generated by `znn-typescript-sdk`'s
  `KeyStore`, using index-0 of the derived key pair as the wallet's single
  address. The mnemonic is encrypted at rest in this browser profile's
  IndexedDB; the encryption password is never sent anywhere.
- `Reveal seed` is the only action that decrypts and displays the mnemonic.
  It requires the literal confirmation `REVEAL SEED` through the agent API
  (`window.zwap.revealMnemonic`), and the human UI gates it behind an
  explicit button press. The revealed words never reach the activity log,
  the status toast, or any network request.
- On connect, the page verifies the configured node's `chainIdentifier`
  against `VITE_ZENON_CHAIN_ID`. A mismatch blocks trading with an explicit
  banner rather than silently signing against the wrong network — see
  `ChainMismatchError` in `src/zenon/sdk-node.ts`.
- Balances, plasma, and unreceived-block counts come from whichever node
  `VITE_ZENON_NODE_WS` points at. That node is your only view of the chain;
  see the trust-boundary note in
  [ADR 0006](../adr/0006-zenon-htlc-settlement.md).
- Zenon requires the recipient to explicitly receive an incoming block.
  Fund a wallet from an external wallet —
  [go-syrius](https://github.com/0x3639/go-syrius) or
  [nom-webwallet](https://github.com/digitalSloth/nom-webwallet) — then press
  **Receive pending** on the target tab; the button's label shows how many
  blocks are waiting. Settlement HTLC unlocks and refunds also arrive as
  pending blocks and need the same explicit receive.
- Every account block — a plain send, an HTLC `Create`/`Unlock`/`Reclaim`, or
  a receive — needs fused plasma or proof-of-work. On mainnet, **Fuse
  plasma** asks the community bot at `https://plazma.bot`
  (`VITE_PLASMA_BOT_URL`) to fuse QSR for the address; fusing takes a few
  minutes to become spendable. When no plasma bot is configured (the
  testnet default, and any deployment with `VITE_PLASMA_BOT_URL` unset), the
  wallet computes proof-of-work in a background Web Worker instead — this
  can take tens of seconds per block.
- Mainnet is real funds. The masthead badge reads "MAINNET · REAL FUNDS" when
  `VITE_ZENON_CHAIN_ID` is `1`, and a plain network/chain-id badge otherwise.
  There is no testnet faucet or plasma bot today, so most manual testing uses
  small mainnet amounts — see [the manual swap guide](manual-swap.md).
- Browser data is local. Clearing site data or pressing **Erase local
  wallet** destroys the encrypted mnemonic; without a written-down backup,
  any funds on that address become unrecoverable through this wallet.
  **Erase everything and restart** additionally clears the order-key store,
  trade-session journal, and order outbox for this profile.
- When the Web Locks API is unavailable, zwap falls back to single-tab mode
  so wallet actions still work, but cross-tab serialization is not provided.
  Do not open the same `?wallet=` profile in more than one tab in that
  fallback mode.
- A crash between a chain accepting a block and IndexedDB persisting its
  local record can leave a session's local journal slightly behind the
  chain. On reload, `advanceTrade`/`runUntilSettled` re-derive the correct
  next action from the node rather than trusting stale local state, so this
  does not lose funds — see the idempotency notes in
  [ADR 0006](../adr/0006-zenon-htlc-settlement.md#completelock-is-idempotent-claims-and-refunds-are-not).

Use `?wallet=maker` and `?wallet=taker` for two isolated actors in one
browser profile. Use a browser with Web Locks for workflows that open the
same profile in multiple tabs.
